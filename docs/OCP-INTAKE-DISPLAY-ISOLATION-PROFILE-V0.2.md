# OCP 문서 분해·표기·격리 프로필 v0.2

> 서로 다른 원본을 보존하면서 내부 업무와 세계 지식을 하나의 검토 가능한 지도에 투영한다.

**상태:** 규격 제안 · 비정본  
**기록일:** 2026-08-27 KST  
**의존 문서:** `OCP-FEDERATED-WORK-CAPABILITY-PLATFORM.md`, `OCP-COLLABORATION-DOMAIN-PROFILE-V0.1.md`  
**범위:** 원문 반입, 분해, 교차 맥락, 격리, 시간·위계·경로 투영

## 1. 한국어 우선 원칙

화면, 문서 제목, 입력 양식, 상태 라벨은 한국어를 우선한다. 파일 형식, 외부 규격, 응용 프로그램 연결, 안정적인 기계 식별자처럼 상호운용에 필요한 경우에만 영문을 유지한다. 내부 코드 값과 사용자 표시명은 분리할 수 있다.

## 2. 원본과 파생 데이터

1. 원문은 수정하지 않고 한 번만 보존하거나 안정적인 외부 원본에 고정한다.
2. 분해된 주장·관계·상태·가설은 원문과 다른 레코드다.
3. 모든 파생 레코드는 원문 식별자와 원문 안 위치로 돌아갈 수 있어야 한다.
4. 원문, 추출, 번역, 추론, 승인, 적용 상태를 합치지 않는다.
5. 화면 위치와 Canvas 선은 정본 데이터가 아니라 투영이다.

## 3. 두 계층

| 계층 | 주체 유형 | 목적 |
| --- | --- | --- |
| 내부 | 개인 · 브랜드/프로젝트/프로덕트 · 컴퍼니/조직/그룹 | 실제 상태, 협업, 고통–필요–목표, 자원과 실행 관리 |
| 세계 | 대표 개인 · 학문/직역/분야 · 도구/플랫폼/커뮤니티 | 외부 기준, 스펙트럼, 연대기, 선례와 선택지 |

두 계층은 새 정본 엔터티 종류를 추가하지 않는다. 승인 전에는 기존 정본 객체·명제·흐름·역량·제공자 위의 도메인 라벨과 투영 규칙이다.

## 4. 최소 레코드

| 레코드 | 필수 값 |
| --- | --- |
| 원문 | 원문ID, 원본 위치, 매체, 기록 시각, 해시(가능한 경우) |
| 사건 | 사건ID, 유효 시각, 기록 시각, 참여 주체 |
| 주장 | 주장ID, 대상, 내용, 지식 유형, 원문 위치, 근거 상태 |
| 주체 | 주체ID, 표시명, 주체 유형 |
| 교차 맥락 | 맥락ID, 참여 주체, 역할, 범위, 유효 기간 |
| 상태 | 상태ID, 주체/맥락, 관측값, 유효 시각, 기록 시각 |
| 관계 후보 | 시작ID, 관계 유형, 끝ID, 근거 주장, 승인 상태 |
| 지표 후보 | 지표ID, 목표, 산식, 단위, 기간, 데이터 원천, 소유자 |

## 5. 겹치는 영역: 교차 맥락

개인–개인, 개인–브랜드, 개인–회사처럼 주체가 겹치는 데이터는 원문을 여러 폴더에 복사하지 않고 별도 `교차 맥락`으로 표현한다.

```text
원문 1개
  → 주장 여러 개
  → 참여 주체와 역할
  → 교차 맥락 1개 이상
  → 개인·프로젝트·조직 보기에 동일 식별자로 투영
```

같은 주장은 여러 보기에 나타날 수 있지만 정본 식별자는 하나다. 맥락마다 역할, 공개 범위, 유효 기간, 고통–필요–목표를 따로 기록할 수 있다.

## 6. 고통–필요–목표

- **고통:** 줄이려는 경험, 손실, 마찰 또는 위험. 왜 필요한가를 설명한다.
- **필요:** 목표 달성에 필요한 조건. 해야 할 일이나 방법 후보와 같지 않을 수 있다.
- **행동:** 누가, 무엇을, 언제, 어디에서 수행하는가.
- **목표:** 성공 여부를 관측할 수 있는 목표 상태.
- **보상:** 해결 뒤 얻는 효용과 피드백.

모든 항목에 최초 발생 시각, 원문 발생 위치, 관측자, 근거, 승인 상태를 연결한다. 알 수 없는 시각은 추정하지 않고 미상으로 둔다.

## 7. 핵심지표

자동 추출된 핵심지표는 `지표 후보`다. 목표, 산식, 단위, 기간, 갱신 주기, 원천 데이터, 담당자, 기준값, 목표값, 승인 상태가 있어야 정식 지표로 승격한다. 분모와 측정 원천이 없는 백분율은 허용하지 않는다.

## 8. 격리와 켜기/끄기

격리 토글은 **조회와 화면 투영을 제어**하며, 원문 이동·삭제나 접근 권한 변경을 의미하지 않는다.

권장 구간은 `나만`, `지정 협업자`, `내부 조직`, `실험`, `공개 가능`이다. 여러 주체가 겹치면 가장 제한적인 구간을 기본 상속한다. 공개 가능 상태는 별도 승인 없이는 켜지지 않는다. 표시 토글은 원본 저장소 권한을 우회할 수 없다.

## 9. 검증 표기

흐름은 `대상 → 산출물 → 근거 상태 → 검증 가능성 → 정당화/승인`이다.

권장 상태는 `원문`, `관측`, `해석 후보`, `관계 후보`, `검증 중`, `반증됨`, `승인됨`, `대체됨`이다. 각 주장에는 지식 유형, 학문 좌표, 근거, 반증 조건, 판단 주체, 승인자를 연결할 수 있다.

로그인이 필요한 공개 링크가 원격 작업 환경에서 열리지 않을 경우 `접근 불가`로 확정하지 않고 `인증 환경 필요`로 표시한다. 링크 소유자의 브라우저와 원격 작업 환경은 서로 다른 인증 경계다.

## 10. 시간과 화면

- Canvas: 작성과 실행 흐름의 중심
- 그래프: 실제 객체·명제·출처·의존 관계
- 타임라인: 유효 시각과 기록 시각
- 피라미드/트리: 개념·모듈·모델·프로젝트 위계
- 표/보드: 정확한 필드와 운영 상태
- 외부 화면 도구: Obsidian이 표현하지 못하는 지도·대시보드·상호작용

외부 화면도 같은 식별자와 원본 경로를 사용해야 한다. 데이터가 논리적으로 하나라는 뜻은 모든 파일을 한 물리 저장소에 복제한다는 뜻이 아니다.

상태 갱신은 `즉시 반응`, `세션`, `일`, `월`, `연`, `목표 기간`, `느린 자동 갱신`으로 나눈다.

## 11. 스펙트럼과 길안내

내부 상태와 세계 기준을 같은 축에 놓되, 외부 스펙트럼 밖의 값은 자동으로 장점이나 결함이 아니다. 각각 `차별점 후보`와 `취약점 후보`로 분기해 검증한다.

길안내 목적은 다음 세 가지다.

1. 개체 또는 집단이 정의한 최상의 컨디션에 도달
2. 외부 선택지에서 수익·비용·시간의 적합점 탐색
3. 사용자가 지정한 목표에 도달

최적 경로는 단순히 간선 수가 가장 적은 길이 아니다. 기대수익, 현금비용, 시간, 위험, 고통, 가역성, 근거 신뢰도를 비용 벡터로 두고 사용자 승인 가중치를 적용한다. 결과는 대안 경로와 선택 이유를 함께 보여야 한다.

## 12. REP와 OCP 흐름

### REP A형 — 신규 데이터 형성

신규 관측/수집/도구/규격 후보 → 선정 → 원자료 → 메타데이터 → 데이터베이스 → 패턴 후보 → 모듈 후보 → 모델 규격 후보 → 시간 변화 → 연대기 → 상태

### REP B형 — 데이터베이스 연결

연결 후보 조사 → 결합형 데이터베이스 → 패턴 후보 → 모듈 후보 → 모델 규격 후보 → 시간 변화 → 연대기 → 상태

### OCP 전면

고통·욕망·필요·문제·이슈·갈등 → 감지 → 수집 → 분석 → 문제 정의 → 상태 표시

### OCP 후면

의사결정 → 해결책 탐색 → 해결안 제시 → 도구/역할 탐색 → 자원 투입 결정 → 해결 → 피드백 → 보상

## 13. 뇌 모방 유비

| 층 | 관찰 대상 | OCP 기능 후보 |
| --- | --- | --- |
| 물리 구조 | 영역·연결·저장 위치 | 데이터 보존, 모듈 경계, 연결망 |
| 전기 신호 | 빠른 전달과 활성 | 즉시 화면, 사건 처리, 세션 상태 |
| 호르몬 | 느리고 넓은 조절 | 장기 상태, 우선순위, 보상·위험 조절 |

이 표는 제품 설계를 위한 유비이지 신경과학적 동등성 주장이 아니다. 한 개념의 원문·근거·반례·상하위·보조개념 시각화와 `엔그램 모방`은 별도 과학 검증이 필요한 가설이다.

## 14. 완료로 주장하지 않는 범위

- 임의 문서 자동 분해 정확도
- 길안내 비용 함수와 추천 성능
- 뇌·신경·호르몬 대응표의 과학적 타당성
- 외부 앱 로그인·원본 반입 어댑터
- 모바일 기기 메모리 공유의 가능성과 효용
- 웹 게시 화면과 접근 통제
- 모든 협업 사례의 MVP 통과

이 프로필은 위 항목의 규격 후보를 제공할 뿐 구현·실행·성과를 증명하지 않는다.
